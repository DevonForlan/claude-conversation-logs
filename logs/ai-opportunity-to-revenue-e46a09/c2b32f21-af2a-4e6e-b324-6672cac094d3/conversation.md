# 二、研究原則：Evidence First

這是一個 Evidence-first 任務。

所有重要商業結論都必須優先使用可驗證證據。

禁止：

- 因為某人在網路上聲稱「月入多少」就視為收入證據
- 把 GitHub Star 當成收入證明
- 把 Product Hunt 熱度當成付費需求
- 把 Reddit 討論直接當成市場驗證
- 把 X / Twitter 貼文當成已驗證收入
- AI 自己猜市場規模
- AI 自己創造不存在的收入案例
- 因為技術上做得到，就推論有人願意付錢
- 因為平台存在，就推論台灣一定可以參與或收款
- 因為有 Bounty 金額，就推論一定可以收到款
- 因為有 Job Posting，就推論客戶一定會聘用

所有重要結論標示：

```text
VERIFIED
PARTIALLY VERIFIED
UNVERIFIED
UNKNOWN
```

並保留來源。

若資料不足：

```text
UNKNOWN
```

不要自行補估算值。

# 三、證據品質分級

對重要資料建立 Evidence Level。

## Level A — Primary Evidence

例如：

- 官方文件
- 官方 Pricing
- 官方 Terms
- 官方 API
- 官方 Help Center
- GitHub Issue
- GitHub Repository
- Bounty 官方頁面
- Platform 官方付款說明
- 官方 KYC / Eligibility 文件

## Level B — Strong Secondary Evidence

例如：

- Maintainer comment
- Verified user transaction record
- Public payout record
- GitHub PR + Bounty payment record
- Platform transaction history
- 官方合作夥伴文件

## Level C — Weak Evidence

例如：

- Reddit
- Blog
- YouTube
- X
- 個人收入分享
- Marketing page
- AI-generated summary

Level C 只能作為線索，不得單獨支撐重大決策。
